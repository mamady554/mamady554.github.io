☁️ Cloud Security · AWS · Terraform

AWS Automated Incident Response Pipeline

Aug 2026

An event-driven cloud security architecture designed to detect, isolate, and preserve evidence from compromised AWS assets automatically. Built using Terraform, this project leverages AWS GuardDuty for continuous threat detection, EventBridge for real-time event routing, and AWS Lambda functions to isolate affected EC2 instances via security group updates while taking forensic disk snapshots. Key steps: initialized tfenv in CloudShell for consistent Terraform versioning, codified an inline Python Lambda handler with least-privilege IAM policies using boto3 to isolate compromised instances, and configured an EventBridge rule to filter GuardDuty high-severity findings (severity 7.0–8.9) and route them to Lambda. Verified the full pipeline end-to-end: ran terraform plan/apply to provision 8 security and automation resources (a zero-ingress/egress isolation security group, IAM policies, Lambda triggers, EventBridge targets), simulated a GuardDuty UnauthorizedAccess:EC2/TorIPCaller finding, confirmed the Lambda executed and isolated the instance, verified forensic EBS snapshot creation and incident tagging, and wired a Slack webhook app ("Security Bot") so containment alerts post to the SOC channel in real time — all validated through CloudWatch execution logs.

🐳 DevSecOps · Docker · OWASP ZAP

Automated DAST Pipeline for Containerized Web Apps

2026

Built an automated Dynamic Application Security Testing (DAST) pipeline for containerized web applications using Docker and OWASP ZAP. The pipeline spins up the target application and a ZAP scanning container, runs an automated active/passive scan against the running app, and produces a structured vulnerability report — the same approach used in enterprise DevSecOps pipelines to catch issues like XSS, injection flaws, and insecure headers before code reaches production. This project was about integrating security testing directly into the deployment workflow instead of treating it as a separate, manual step: containerizing both the app under test and the scanner meant the whole pipeline could be reproduced consistently in CI.

🗂️ Identity & Access · Windows Server

Active Directory Domain Services

Jul 2026

Built a complete Active Directory environment from scratch to understand identity and access management the way it's actually run in enterprise environments, not just the GUI wizard. This included promoting a fresh Windows Server 2022 install to a domain controller, designing an OU structure that mirrors real-world geographic/departmental hierarchies, creating security groups following the AGDLP model, and configuring new-hire user provisioning with enforced first-login password resets. Also configured DNS and DHCP to support AD's SRV record dependencies, and worked through Group Policy scoping issues firsthand — including a GPO linked too broadly that overwrote user settings domain-wide, reinforcing why OU-level scoping and testing matter. User lifecycle management: created user accounts for new employees with default passwords that force a reset on first login, organized security groups so each user only has access to what their role needs (e.g. an IT group with scoped resource access), and can disable, remove, reset, or re-enable accounts in AD when someone leaves the company or has account issues.

Help Desk Ticketing Lab — osTicket, Docker & MySQL

May 2026

Deployed a fully functional help desk ticketing system locally using Docker and MySQL with no cloud and no cost. Configured two containers (osTicket and MySQL) from scratch using docker-compose, resolved real deployment errors including architecture mismatches and missing environment variables, and walked through the complete ticket lifecycle from submission to documented closure. Practiced the same workflows used in enterprise ITSM environments including triaging incoming requests, setting priority levels, responding to users, writing internal resolution notes, and closing tickets with an audit trail. This mirrors day-to-day operations in tools like ServiceNow and Jira Service Management. Workflow covered: created the project directory and .env file to store MySQL credentials securely, wrote the docker-compose.yml defining both services with port mapping and persistent volume storage, launched both containers and verified with docker ps, logged into the osTicket Staff Control Panel, submitted a test ticket as a user, triaged and flagged it high priority in the admin queue, replied to the user, and closed the ticket with full resolution notes — a complete, auditable ticket lifecycle.
